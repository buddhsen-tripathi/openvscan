---
title: Repository settings
description: Every per-repository review setting, what it does, and its default.
---

Each connected repository has its own review policy. To change it, open **Repositories**, pick the repository and switch to the **Review policy** tab. A bar appears at the bottom while you have unsaved changes; click **Save changes**. Changes apply from the next review. A review already in progress keeps the settings it started with.

## Settings

| Setting | Default | What it does |
|---------|---------|--------------|
| **Review pull requests** | Every push | When pull requests are reviewed without being asked: **Every push**, **When opened** or **Only on request**. |
| **Skip drafts** | On | Ignores draft pull requests until they are marked ready for review. |
| **Target branches** | All | Only pull requests into these base branches are reviewed automatically. |
| **Scanners** | All five | Which scanners run. See [Scanners](/docs/scanners). |
| **AI reviewer** | None | **None** runs scanners only. **Claude Code**, **Codex** or **Cursor** adds the AI review. See [AI review](/docs/ai-review). |
| **Model** | Default | The agent's default, a model alias, or a custom model id. |
| **Focus areas** | None | Extra checklists added to the reviewer's prompt. |
| **Review skills** | None | Markdown skills the reviewer reads and applies. See [Review skills](/docs/review-skills). |
| **Instructions** | Empty | Extra guidance added to the end of the agent's prompt. |
| **Fail the check on** | High or above | The lowest severity that fails the check. |
| **Ignored paths** | Empty | Globs for files whose findings are dropped. |

**Model**, **Focus areas**, **Review skills** and **Instructions** appear only when an AI reviewer is selected.

You must keep at least one scanner or an AI reviewer on. Saving with neither fails with "Enable at least one scanner or an AI agent".

### Review pull requests

| Option | Pull request events that start a review |
|--------|------------------------------------------|
| **Every push** | `opened`, `synchronize`, `reopened`, `ready_for_review` |
| **When opened** | `opened`, `reopened`, `ready_for_review`. New commits are not reviewed until someone asks. |
| **Only on request** | None. Reviews run only from a [comment command](#pull-request-commands), **Re-run** or **Review a branch**. |

### Skip drafts

With this on, opening or pushing to a draft pull request does nothing. Marking it ready for review starts a review. Turn it off to review drafts too.

### Target branches

A comma-separated list of base branch names, such as `main, release`. Pull requests into other branches are not reviewed automatically, but a comment command still reviews them. Leave it empty to review pull requests into any branch.

### AI reviewer

The AI reviewer uses the credential of the person who connected the repository. If they have not saved a credential for the selected agent, the settings show a warning, and reviews run the scanners only until a credential is added. See [Agent credentials](/docs/agent-credentials).

### Model

Pick **Default** to let the agent CLI choose. For Claude Code you can also pick **Sonnet**, **Opus** or **Haiku**; these aliases always point at the newest model of that tier. **Custom model id** takes any value the CLI accepts with `--model`: letters, digits and `.`, `:`, `/`, `-`, `_`, up to 100 characters. OpenVScan does not check that the model exists. If the agent rejects it, the AI review fails with the agent's error and the scanner results are still published.

### Focus areas

Each focus area adds a short checklist to the prompt: **Web app**, **API and backend**, **CI and infrastructure**, **LLM and agents** and **Secrets and crypto**. Pick the ones that describe the codebase. With none selected the agent does a general review.

### Review skills

Tick the skills this repository's reviews should use: OpenVScan's built-ins (OWASP ASVS checklist, API security, LLM application security, CI/CD security) and the skills you added in **Settings → Review skills**. **Manage skills** links there. Up to 20 per repository. If the selected skills add up to more than 120 KB, the ones you ticked first are kept. See [Review skills](/docs/review-skills) for how to add and write them.

Focus areas are a sentence or two each; skills are full checklists. They work together.

### Instructions

Up to 4,000 characters of guidance for the agent, added to the prompt as the repository owner's instructions. Unlike the pull request's content, these instructions are treated as trusted, because only you can set them. Use them to describe your codebase's conventions and what matters most. For example:

```text
All SQL goes through db/query.ts; treat raw string concatenation there as critical.
```

### Ignored paths

One glob per line. `*` matches within a path segment, `**` across segments and `?` one character. A pattern without a slash matches the file name anywhere, like `.gitignore`; a pattern ending in `/` covers everything below that directory. Findings from scanners and the agent in matching files are dropped, and the agent is told to skip them. For example:

```text
vendor/**
**/fixtures/**
*.min.js
```

### Fail the check on

The check fails when a finding at or above this severity is in the diff and was not dismissed by the agent as a false positive. **Never** makes every review neutral and advisory. See [Results on GitHub](/docs/results-on-github#pass-fail-or-neutral) for the full rule.

## Pull request commands

People with write access to the repository (owner, member or collaborator) can comment on a pull request to drive OpenVScan. Mention the App by its slug:

| Command | What it does |
|---------|--------------|
| `@<app> review` | Reviews the pull request's latest commit now, whatever the trigger setting. |
| `@<app> pause` | Stops automatic reviews on this pull request. |
| `@<app> resume` | Turns automatic reviews back on for this pull request. |
| `@<app> help` | Replies with the list of commands. |

OpenVScan reacts with 👀 when it accepts a command. Comments from anyone else, and from bots, are ignored. The **Review policy** tab lists the commands with your App's slug. Commands need the App subscribed to the **Issue comment** event; see [GitHub App](/docs/github-app).

## Review a branch

The **Review a branch** panel on the repository's **Overview** tab starts a review on demand. Enter a branch name, or leave it empty to use the default branch, and click **Run**.

A branch review differs from a pull request review:

- It scans the whole tree at the branch's latest commit. There is no diff, so every finding counts toward the conclusion.
- It posts a check run on that commit, but no inline comments or summary comment.
- If an AI reviewer is set, the agent reviews the whole repository, starting with the most security-sensitive code.

## Disconnect a repository

**Disconnect**, under **Danger zone** on the **Review policy** tab, cancels any review in progress and removes the repository from OpenVScan, along with its review history in the dashboard. Pull requests on it are no longer reviewed.

Disconnecting does not change the GitHub App's access. To remove access, use **Manage on GitHub** on the **Repositories** page. When you remove a repository from the App installation on GitHub, or uninstall the App, OpenVScan removes the affected repositories automatically.

A repository can be connected to only one OpenVScan account at a time.
