---
title: Agent credentials
description: Connect Claude Code or Codex with your own token or API key, and how OpenVScan stores and uses it.
---

The AI review runs on your own model credential. OpenVScan never supplies one. You save it once under **Settings** in the **AI agents** section, and every repository you connect can use it.

## Credential types

| Agent | Credential | How to get it |
|-------|------------|---------------|
| Claude Code | Claude subscription token | Run `claude setup-token` and paste the token. Uses your Claude Pro or Max plan. |
| Claude Code | Anthropic API key | Create a key at console.anthropic.com. Billed by usage. |
| Codex | OpenAI API key | Create a key at platform.openai.com. Billed by usage. |

To create a Claude subscription token, run this on a machine where you are logged in to Claude Code:

```bash
claude setup-token
```

## Add a credential

1. Open **Settings** and go to the **AI agents** section. The user menu's **AI agents** item goes to the same page.
2. On the **Claude Code** card, choose **Claude subscription token** or **Anthropic API key**. The **Codex** card takes an **OpenAI API key**.
3. Paste the value into **Token** and click **Save credential**.

The card then shows **Connected**, the credential type, its last four characters and when it was last used ("Not used yet" until the first review).

A saved credential is not used until a repository asks for it. Set **AI reviewer** to the matching agent on each repository you want reviewed. See [Repository settings](/docs/repository-settings).

OpenVScan rejects values shorter than 20 or longer than 4,000 characters, and values containing spaces or line breaks. It also catches the common mix-up of pasting one type as another, for example an `sk-ant-api` key into the subscription token field.

## One credential per agent

You can hold one credential for Claude Code and one for Codex. The Claude Code slot holds either a subscription token or an API key, not both.

To change a credential, click **Replace** on its card and save a new value. It overwrites the old one. To remove it, click the trash icon. Repositories set to that agent then run scanners only, and the summary comment says the AI review did not complete because no credential is configured.

## Whose credential a review uses

A review uses the credential of the OpenVScan user who connected the repository. It does not use the pull request author's credential.

Every pull request on that repository spends that user's quota or API budget. This includes pull requests from forks, which anyone can open on a public repository. If that is a concern, set **AI reviewer** to **None** for that repository or turn off **Review pull requests**.

## How it is stored

Credentials are encrypted at rest with AES-256-GCM. The key is `CREDENTIALS_KEY`, a secret configured on the deployment. Each credential gets a random 12-byte IV, and its database row id is bound in as additional authenticated data, so an encrypted value cannot be copied to another row and still decrypt.

The plaintext is never sent back to your browser. The dashboard only receives the type, the last four characters and timestamps.

## How it is used

The credential never enters the sandbox where the agent runs.

1. When the AI step starts, the engine decrypts the credential.
2. The engine switches the sandbox's egress policy to the agent phase and holds the secret in that policy, in memory.
3. The agent CLI starts with a placeholder value (`openvscan-injected-at-egress`) in place of the real token or key.
4. When the agent calls the model API, the egress proxy replaces the placeholder with the real credential. It does this only for `api.anthropic.com` (Claude Code) or `api.openai.com` (Codex), and blocks every other host.
5. When the agent finishes, egress is locked again and the sandbox is destroyed.

The secret is never written to the container's environment, its files or Durable Object storage. See [Security model](/docs/security-model).

<Callout type="warning" title="Subscription tokens on a shared service">
Check your model provider's terms before connecting a subscription token to a service someone else operates. API keys are the safe default for a hosted, multi-user deployment. Self-hosters using their own subscription for their own repositories are the intended case for subscription tokens.
</Callout>

## Self-hosted deployments

Saving credentials requires `CREDENTIALS_KEY` to be set on both the web and engine Workers, with the same value. Without it, the **AI agents** section shows a warning and the save button is disabled. See [Self-hosting](/docs/self-hosting).
